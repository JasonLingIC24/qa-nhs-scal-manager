Demonstrate technical conformance for the PDS FHIR API

Audit history

There is a problem

    The PDS FHIR API enables access to the Personal Demographics Service (PDS) - the national electronic database of NHS patient details such as name, address, date of birth, related people and NHS number.

    The API has three access modes, providing differing authentication methods and functionality. Which access mode(s) your software uses affects the technical conformance criteria required.

    Help and tips for completing this section

    The following resources provide more details on how to complete technical conformance for the PDS FHIR API:

    • PDS FHIR API specification

    Important

    This section is for healthcare worker and application-restricted access modes only. If patient access mode is required, you need to select this separately from the APIs to be used menu.

    End user authentication

    • Get patient details
    • Optional: Update patient details

    PDS-FHIR-NALL 02

    Before allocating an NHS Number do you ensure that the patient does not have an NHS Number by performing patient searches on the PDS?

    Supporting information

    A PDS search MUST be undertaken ahead of new NHS number allocation, to avoid duplicate records being created.

    This is not relevant when creating a record for a baby at birth as there is built-in duplicate checking when the submitted information is validated.

    However, if it is necessary to create a record for the mother, it should be checked that they do not already have a record.
